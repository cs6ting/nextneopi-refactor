Scientific Capability Contract · IF-VAR-004

BuildConsensusSomaticCallset高置信体细胞变异共识接口

将多个已规范化 caller callset 按版本化科学策略合并。首版保留 primary caller 的记录，只接受至少由一个 confirming caller 支持的同一规范 allele，并为每个决策保留可审计 provenance。

Proposed Contract 1.0.0 MOD-05 WES · WGS SNV · INDEL Pure Python

当前代码映射 旧实现位于 bin/make_hc_vcf.py，由 nextNEOpi.nf 的高置信 VCF 流程调用。目标设计将 caller FORMAT 归一化、领域共识和 VCF renderer 拆成三个独立职责。

目的与科学语义

设 P 为 primary caller 的规范 allele 集合，C₁…Cₙ 为成功完成的 confirming caller 集合。高置信集合只取 primary 子集：

HC = { v ∈ P | |support(v)| ≥ minimum_callers }

默认 minimum_callers = 2，计数包含 primary，即至少需要一个 confirming caller 支持。

Rule 01

Primary 是候选边界

confirming-only allele 永远不会进入高置信输出。

Rule 02

Exact allele identity

支持必须匹配规范 REF/ALT，不允许只比较 CHROM:POS。

Rule 03

Failure is not empty

失败 caller 不能当作“成功但未检出”。

关键科学风险 旧脚本使用 walk_together 同步记录，但共识逻辑没有显式比较 ALT。重构必须覆盖“同位置不同 ALT”，并将差异标记为经批准的科学修正，而不是简单放宽等价测试。

数据流

职责边界

本接口负责

  • 验证 callset 兼容性与可用状态
  • 按规范 allele identity 查找支持
  • 执行 primary-confirmed policy
  • 生成 confirmed 与 primary-only 分区
  • 生成逐 allele decision/provenance
  • 保证排序、缓存和输出确定性

本接口不负责

  • 执行 Mutect2、VarScan2、Strelka2、Mutect1
  • 解释 caller 原生 FORMAT
  • left normalization 或多等位拆分
  • 自动选择 primary caller
  • VEP、phase、CCF 或 TMB
  • 宣称不同 caller 科学等价

关键不变量

Allele identity

只有 assembly、规范 sequence、1-based position、left-normalized REF/ALT 和 normalization version 全部一致，才算同一 allele。

chr1:100 A>C  !=  chr1:100 A>G

chr1:100 AT>A == equivalent indel representation
                  only after IF-VAR-003 normalization

集合分区

confirmed ⊆ primary · primary_only ⊆ primary
confirmed ∩ primary_only = ∅
confirmed ∪ primary_only = primary
完整性要求每个 primary allele 恰好产生一条 decision；每个 accepted decision 的支持数必须达到 minimum_callers。

算法契约

Reference pseudocode 
def build_primary_confirmed_consensus(request):
    validated = validate_request(request)
    primary = validated.primary_callset
    indexes = index_confirming_callsets_by_exact_allele(validated)

    confirmed = []
    primary_only = []
    decisions = []

    for variant in stream_variants(primary):
        allele = variant.allele_identity
        supports = [support_from_primary(primary, allele)]

        for caller, index in indexes.items():
            match = index.find_exact(allele)
            if match is not None:
                supports.append(support_from_match(caller, match))

        accepted = len(supports) >= request.policy.minimum_callers
        target = confirmed if accepted else primary_only
        target.append(preserve_primary_record(variant, supports))
        decisions.append(make_decision(allele, supports, accepted))

    assert_partition_invariants(primary, confirmed, primary_only)
    return commit_typed_outputs(confirmed, primary_only, decisions)

输出不得依赖输入 caller 顺序、文件系统 glob 顺序或 Python hash 随机化。support 顺序固定为 primary 第一，其余按 implementation ID；VCF 按 reference dictionary 与 allele 排序。

配置

YAML 
methods:
  somatic_callers:
    - mutect2
    - varscan2
    - strelka2

policies:
  somatic_consensus:
    implementation: primary_confirmed_v1
    strategy: primary_confirmed
    primary: mutect2
    minimum_callers: 2
    on_failed_confirming_caller: fail
    preserve_primary_representation: true

方法和策略分开：methods 只声明 caller，policies 定义共识。配置校验必须确保 primary 在 caller 列表中、minimum 合法，且失败后可用 caller 数仍满足 policy。

执行、Scatter/Gather 与资源

Scatter/Gather

  • 按 reference dictionary 的 contig scatter。
  • 每个 shard 同时接收 primary 与所有 confirming 分片。
  • 无记录的 caller 仍提供 typed empty shard。
  • 必须等待全部 shard；不允许 partial gather。
  • Gather 后再次验证分区和总计数。

资源模型

  • 纯 Python / htslib-backed transform。
  • 默认 1 CPU、2 GiB RAM、4 GiB scratch。
  • 总 VCF 大于阈值时按 contig scatter。
  • 优先流式读取，禁止默认全量载入 WGS VCF。
  • 不需要第三方算法许可证。
resources:
  cpus: 1
  memory_mb: 2048
  runtime_minutes: 60
  scratch_mb: 4096
  scaling_model: >-
    memory=max(2048, total_vcf_gib*512);
    scatter_by_contig_when_total_vcf_gib>4

Cache 与 Provenance

Cache key 必含

Contract/implementation version、primary、minimum、失败策略、所有 caller ID/version/checksum、normalization contract、reference dictionary、renderer schema。caller 输入顺序先规范排序；CPU/partition/account 默认不进入科学 key。

验收条件

  • Request/Result 与 JSON Schema 完整，公共 API strict typed。
  • 领域实现为纯 Python，无第三方工具调用。
  • 同位置不同 ALT 不被确认。
  • 失败 caller 不被当作 empty。
  • confirmed、primary-only 和 support 工件原子提交。
  • Local/Slurm、scatter/non-scatter 规范结果一致。
  • 每个 allele 可追踪到 caller/version/input artifact。
  • 领域分支覆盖率不低于 90%，全部门禁通过。
  • 接入 wes_dna_canonical 并有可重复 Demo。
  • 旧/新科学等价报告无未解释差异。

Reference API

nextNEOpi Reference API

设计版本：0.1 · Python API 基线：v1 · 状态：Proposed

本目录定义重构后 nextneopi Python package 的公共接口，是后续实现、测试和插件开发的直接契约。组织方式参考 PyTorch Reference API：顶层按 namespace 索引，namespace 页面先列 API Summary，再展开签名、参数、返回值、异常与示例。参考页面仅用于信息架构研究，本文内容均根据 nextNEOpi 需求重新设计。

Python API

Namespace 用途
nextneopi 顶层便捷函数和稳定 re-export
nextneopi.config 版本化配置、加载、合并和 Schema
nextneopi.models 领域实体、工件、状态、任务和结果模型
nextneopi.application Client、planner、selector 和 recipe registry
nextneopi.ports Execution、Artifact、Container、Plugin、Provenance 端口
nextneopi.plugins 插件 descriptor、实现协议和 entry point

nextneopi.errors 异常、错误类别和错误码

使用边界

这些接口是目标系统设计，尚不代表当前仓库已有可导入的 nextneopi package。实现必须：

  1. 遵守本文签名和科学语义；
  2. 通过对应 Unit/Contract/Integration/Scientific tests；
  3. 对破坏性变化提升 contract major；
  4. 不通过 dict[str, Any]、裸路径或通用 run_tool() 绕过类型；
  5. 不把 EMPTY、NOT_REQUESTED、SKIPPED_UNSUPPORTED 和 FAILED 混用。

首轮科学对照覆盖配对 WES DNA 至常规候选全量表和过滤表。固定输入、工具和策略验证同方法等价，二级候选算法通过独立配置比较。 第一层功能设计 · 第二层算法清单 · 验收测试矩阵

离线文档

安装 Pandoc 后，从仓库根目录运行 python3 software_plan/08_api_reference/package_windows.py。生成的浏览入口是 software_plan/08_api_reference/html/index.html，离线压缩包是 software_plan/08_api_reference/dist/nextneopi-api-docs-windows.zip。若更新 software_plan/ 顶层的分发副本，将新压缩包同步到该位置。
